# 代理服务器-节点服务器通讯协议书

## 1. 协议概述

### 1.1 协议简介

本文档详细描述了代理服务器（Proxy Server）与节点服务器（Node Server）之间的通信协议。该协议基于WebSocket实现，用于节点注册、任务分配、状态监控、文件传输等核心功能的通信。

### 1.2 协议版本

- **当前版本**: 1.0
- **协议类型**: WebSocket (RFC 6455)
- **消息格式**: JSON
- **字符编码**: UTF-8

### 1.3 通信架构

```
┌─────────────────┐                    ┌─────────────────┐
│  Proxy Server   │◄──────────────────►│  Node Server    │
│  (代理服务器)    │    WebSocket       │  (节点服务器)    │
└─────────────────┘                    └─────────────────┘
         │                                      │
         │  任务分配、状态监控、文件传输           │
         └──────────────────────────────────────┘
```

### 1.4 系统角色

| 角色 | 职责 |
|------|------|
| Proxy Server | 任务调度、节点管理、资源监控、文件分发 |
| Node Server | 任务执行、状态上报、文件处理、心跳响应 |

## 2. 连接管理

### 2.1 连接端点

| 参数 | 值 |
|------|-----|
| WebSocket URL | `ws://192.168.84.251:8765/node-ws` |
| 协议 | WebSocket (ws://) |
| 超时时间 | 10秒 |
| 重连间隔 | 5秒（指数退避） |
| 最大重连次数 | 10次 |

### 2.2 连接建立流程

```
Node Server                          Proxy Server
     │                                    │
     │───── WebSocket 连接请求 ──────────>│
     │                                    │
     │<───── 连接建立确认 ─────────────────│
     │                                    │
     │───── register 消息 ───────────────>│
     │  (node_id, node_name, capabilities)│
     │                                    │
     │<───── register_response ───────────│
     │  (status: registered)              │
     │                                    │
     │<───── connected 消息 ──────────────│
     │                                    │
     │───── status_report ───────────────>│
     │  (初始状态报告)                     │
     │                                    │
     │<───── heartbeat ────────────────────│
     │  (开始心跳检测)                     │
     │                                    │
     │───── heartbeat_response ──────────>│
     │                                    │
```

### 2.3 连接状态码

| 关闭码 | 描述 | 原因 | 处理方式 |
|--------|------|------|----------|
| 1000 | Normal closure | 正常关闭连接 | 无需特殊处理 |
| 1003 | Registration failed | 无效的 node_id | 检查注册信息并重试 |
| 1006 | Abnormal closure | 连接意外关闭 | 立即尝试重连 |
| 1008 | Invalid message type | 无效的消息类型或格式 | 检查消息格式并修复 |
| 1011 | Internal server error | 服务器内部错误 | 等待一段时间后重试 |

### 2.4 重连机制

Node Server 应实现自动重连机制，采用指数退避策略：

| 重连次数 | 等待时间 |
|----------|----------|
| 第1次 | 5秒 |
| 第2次 | 10秒 |
| 第3次 | 20秒 |
| 第4次 | 40秒 |
| 第5次及以后 | 40秒（固定） |

重连流程：
1. 检测到连接断开
2. 等待退避时间
3. 尝试重新连接
4. 如果连接成功，重新执行注册流程
5. 如果连接失败，增加重连计数并重复步骤2-4
6. 如果达到最大重连次数（10次），停止重连并记录错误日志

## 3. 消息规范

### 3.1 通用消息格式

所有消息必须包含以下基础字段：

```json
{
  "type": "message_type",
  "timestamp": "2023-01-01T12:00:00Z"
}
```

| 字段名 | 类型 | 必选 | 描述 | 格式要求 |
|--------|------|------|------|----------|
| type | string | 是 | 消息类型 | 必须是支持的消息类型之一 |
| timestamp | string | 是 | 消息发送时间戳 | ISO 8601格式 (YYYY-MM-DDTHH:MM:SSZ) |

### 3.2 消息类型总览

| 消息类型 | 发送方 | 接收方 | 描述 |
|----------|--------|--------|------|
| register | Node Server | Proxy Server | 节点注册 |
| register_response | Proxy Server | Node Server | 注册响应 |
| connected | Proxy Server | Node Server | 连接确认 |
| heartbeat | Proxy Server | Node Server | 心跳检测 |
| heartbeat_response | Node Server | Proxy Server | 心跳响应 |
| status_report | Node Server | Proxy Server | 状态报告 |
| task_assign | Proxy Server | Node Server | 任务分配 |
| task_complete | Node Server | Proxy Server | 任务完成 |
| task_failed | Node Server | Proxy Server | 任务失败 |
| file_transfer | 双向 | 双向 | 文件分片传输 |
| chunk_received | 双向 | 双向 | 文件分片接收确认 |
| shutdown | Proxy Server | Node Server | 关闭请求 |

### 3.3 消息验证规则

1. **JSON格式验证**: 消息必须是有效的JSON格式
2. **必填字段检查**: 必须包含 type 和 timestamp 字段
3. **类型验证**: 字段类型必须与规范一致
4. **消息类型检查**: type 必须是支持的消息类型之一
5. **时间戳验证**: timestamp 必须是有效的ISO 8601格式
6. **业务字段验证**: 特定消息类型的业务字段必须符合规范

## 4. 注册机制

### 4.1 注册流程

1. Node Server 建立WebSocket连接
2. Node Server 在连接建立后5秒内发送 register 消息
3. Proxy Server 验证 node_id 的合法性
4. 注册成功：Proxy Server 发送 register_response 消息
5. 注册失败：Proxy Server 关闭连接，状态码 1003

### 4.2 注册消息

**消息类型**: register  
**发送方**: Node Server  
**接收方**: Proxy Server

```json
{
  "type": "register",
  "timestamp": "2023-01-01T12:00:00Z",
  "node_id": "node-001",
  "node_name": "Node Server 001",
  "capabilities": {
    "cpu_cores": 4,
    "memory_gb": 16,
    "disk_gb": 100
  }
}
```

| 字段名 | 类型 | 必选 | 描述 |
|--------|------|------|------|
| node_id | string | 是 | 节点唯一标识符，在配置文件中定义 |
| node_name | string | 否 | 节点名称，用于UI显示 |
| capabilities | object | 是 | 节点能力信息 |
| capabilities.cpu_cores | integer | 是 | CPU核心数 |
| capabilities.memory_gb | integer | 是 | 内存大小（GB） |
| capabilities.disk_gb | integer | 是 | 磁盘大小（GB） |

### 4.3 注册响应消息

**消息类型**: register_response  
**发送方**: Proxy Server  
**接收方**: Node Server

```json
{
  "type": "register_response",
  "timestamp": "2023-01-01T12:00:01Z",
  "status": "registered",
  "node_id": "node-001",
  "message": "Registration successful"
}
```

| 字段名 | 类型 | 必选 | 描述 |
|--------|------|------|------|
| status | string | 是 | 注册状态，值为 "registered" 或 "failed" |
| node_id | string | 是 | 节点唯一标识符 |
| message | string | 否 | 状态描述信息 |

### 4.4 连接确认消息

**消息类型**: connected  
**发送方**: Proxy Server  
**接收方**: Node Server

```json
{
  "type": "connected",
  "timestamp": "2023-01-01T12:00:02Z",
  "node_id": "node-001"
}
```

## 5. 心跳机制

### 5.1 心跳流程

1. Proxy Server 每30秒发送一次 heartbeat 消息
2. Node Server 收到心跳消息后立即回复 heartbeat_response
3. Proxy Server 如果在60秒内未收到响应，标记节点为不健康
4. 心跳超时后，Proxy Server 可关闭连接

### 5.2 心跳消息

**消息类型**: heartbeat  
**发送方**: Proxy Server  
**接收方**: Node Server

```json
{
  "type": "heartbeat",
  "timestamp": "2023-01-01T12:00:30Z"
}
```

### 5.3 心跳响应消息

**消息类型**: heartbeat_response  
**发送方**: Node Server  
**接收方**: Proxy Server

```json
{
  "type": "heartbeat_response",
  "timestamp": "2023-01-01T12:00:31Z"
}
```

### 5.4 心跳超时处理

| 场景 | 处理方式 |
|------|----------|
| 首次心跳超时 | 标记节点为不健康，记录警告日志 |
| 连续3次心跳超时 | 关闭连接，状态码 1006 |
| 心跳恢复 | 标记节点为健康，记录恢复日志 |

## 6. 状态报告

### 6.1 状态报告流程

1. Node Server 定期（默认10秒）发送 status_report 消息
2. Proxy Server 接收并更新节点状态信息
3. 状态信息用于任务调度和资源管理

### 6.2 状态报告消息

**消息类型**: status_report  
**发送方**: Node Server  
**接收方**: Proxy Server

```json

    "disk_usage": 0.75,
```

## 8. 文件传输

### 8.1 文件传输机制

文件传输采用分片传输机制，支持大文件的可靠传输：

1. **文件分片**: 将文件分割为多个小块（建议5MB）
2. **Base64编码**: 每个分片使用Base64编码
3. **MD5校验**: 每个分片和整个文件都计算MD5哈希值
4. **确认机制**: 接收方收到每个分片后发送确认消息
5. **完整性验证**: 传输完成后验证文件完整性

### 8.2 文件传输消息

**消息类型**: file_transfer  
**发送方**: 双向  
**接收方**: 双向

```json
{
  "type": "file_transfer",
  "timestamp": "2023-01-01T12:05:00Z",
  "transfer_id": "task-456",
  "chunk": "base64_encoded_chunk_data...",
  "index": 0,
  "total_chunks": 10,
  "file_hash": "d41d8cd98f00b204e9800998ecf8427e",
  "chunk_hash": "d41d8cd98f00b204e9800998ecf8427e"
}
```

| 字段名 | 类型 | 必选 | 描述 |
|--------|------|------|------|
| transfer_id | string | 是 | 传输唯一标识符（通常为task_id或文件名） |
| chunk | string | 是 | 文件分片数据（Base64编码） |
| index | integer | 是 | 当前分片索引（从0开始） |
| total_chunks | integer | 是 | 总分片数 |
| file_hash | string | 是 | 整个文件的MD5哈希值 |
| chunk_hash | string | 是 | 当前分片的MD5哈希值 |

### 8.3 分片接收确认消息

**消息类型**: chunk_received  
**发送方**: 双向  
**接收方**: 双向

```json
{
  "type": "chunk_received",
  "timestamp": "2023-01-01T12:05:01Z",
  "transfer_id": "task-456",
  "index": 0,
  "status": "ok"
}
```

| 字段名 | 类型 | 必选 | 描述 |
|--------|------|------|------|
| transfer_id | string | 是 | 传输唯一标识符 |
| index | integer | 是 | 已接收的分片索引 |
| status | string | 是 | 接收状态，值为 "ok" 或 "error" |

### 8.4 文件传输流程

#### 8.4.1 任务文件接收流程（Proxy → Node）

1. Proxy Server 将任务文件分割为多个分片
2. Proxy Server 逐个发送 file_transfer 消息
3. Node Server 接收分片并验证 chunk_hash
4. Node Server 发送 chunk_received 确认消息
5. 所有分片接收完成后，Node Server 重组文件
6. Node Server 验证 file_hash 确保文件完整性
7. Node Server 将文件保存到工作目录

#### 8.4.2 结果文件上传流程（Node → Proxy）

1. Node Server 执行任务完成，生成 .grid 和 .line 文件
2. Node Server 将每个文件分割为多个分片
3. Node Server 逐个发送 file_transfer 消息
4. Proxy Server 接收分片并验证 chunk_hash
5. Proxy Server 发送 chunk_received 确认消息
6. 所有分片接收完成后，Proxy Server 重组文件
7. Proxy Server 验证 file_hash 确保文件完整性
8. Node Server 发送 task_complete 消息

### 8.5 文件传输错误处理

| 错误类型 | 检测方式 | 处理方式 |
|----------|----------|----------|
| 分片丢失 | 接收方未收到期望索引的分片 | 发送方重发丢失的分片 |
| 分片校验失败 | chunk_hash 不匹配 | 接收方发送错误确认，发送方重发该分片 |
| 文件完整性失败 | file_hash 不匹配 | 接收方请求重传整个文件 |
| 传输超时 | 未在规定时间内收到分片 | 发送方重发当前分片或中止传输 |

### 8.6 文件传输参数建议

| 参数 | 建议值 | 说明 |
|------|--------|------|
| 分片大小 | 5MB | 平衡传输效率和内存使用 |
| 分片超时 | 30秒 | 单个分片传输的最大等待时间 |
| 最大重试次数 | 3次 | 单个分片的最大重试次数 |
| 文件大小限制 | 1GB | 单个文件的最大大小限制 |

## 9. 关闭机制

### 9.1 关闭流程

1. Proxy Server 发送 shutdown 消息
2. Node Server 停止接收新任务
3. Node Server 等待当前任务完成
4. Node Server 关闭所有连接
5. Node Server 退出程序

### 9.2 关闭消息

**消息类型**: shutdown  
**发送方**: Proxy Server  
**接收方**: Node Server

```json
{
  "type": "shutdown",
  "timestamp": "2023-01-01T18:00:00Z",
  "reason": "Maintenance"
}
```

| 字段名 | 类型 | 必选 | 描述 |
|--------|------|------|------|
| reason | string | 否 | 关闭原因 |

### 9.3 优雅关闭要求

- 禁止直接终止 Node Server 进程
- 必须通过 shutdown 消息触发关闭流程
- 当前执行的任务必须完成才能关闭
- 所有文件传输必须完成才能关闭
- 关闭前应清理临时文件和资源

## 10. 错误处理

### 10.1 连接错误处理

| 错误场景 | 检测方式 | 处理方式 |
|----------|----------|----------|
| 连接断开 | WebSocket连接关闭 | 自动重连（指数退避） |
| 认证失败 | 收到状态码1003 | 检查配置信息后重试 |
| 心跳超时 | 60秒未收到响应 | 主动检查连接状态 |
| 消息格式错误 | JSON解析失败 | 记录错误日志，忽略消息 |

### 10.2 任务错误处理

| 错误场景 | 检测方式 | 处理方式 |
|----------|----------|----------|
| 任务执行失败 | ramgeo返回非零退出码 | 发送 task_failed 消息 |
| 文件传输失败 | 分片校验失败或超时 | 重试或中止任务 |
| 结果文件缺失 | 任务完成后未生成结果文件 | 发送 task_failed 消息 |
| 磁盘空间不足 | 写入文件时失败 | 发送 task_failed 消息 |

### 10.3 错误日志格式

```json
{
  "timestamp": "2023-01-01T12:05:00Z",
  "level": "ERROR",
  "module": "TaskExecutor",
  "message": "Task execution failed",
  "task_id": "task-456",
  "error": {
    "type": "ExecutionError",
    "message": "ramgeo execution failed: Invalid input file format",
    "stack_trace": "..."
  }
}
```

## 11. 安全考虑

### 11.1 数据安全

- 所有传输数据使用Base64编码
- 文件传输使用MD5哈希验证完整性
- 敏感信息（如密码）不应在消息中明文传输

### 11.2 连接安全

- 实现连接超时机制
- 实现消息验证机制
- 防止消息重放攻击（建议使用时间戳验证）

### 11.3 资源保护

- 限制单个文件大小（建议1GB）

### 14.2 消息类型速查表

| 消息类型 | 方向 | 触发条件 | 频率 |
|----------|------|----------|------|
| register | Node → Proxy | 连接建立后 | 一次 |
| register_response | Proxy → Node | 收到注册请求 | 一次 |
| connected | Proxy → Node | 注册成功后 | 一次 |
| heartbeat | Proxy → Node | 定时触发 | 每30秒 |
| heartbeat_response | Node → Proxy | 收到心跳 | 每次 |
| status_report | Node → Proxy | 定时触发 | 每10秒 |
| task_assign | Proxy → Node | 分配任务 | 按需 |
| task_complete | Node → Proxy | 任务完成 | 按需 |
| task_failed | Node → Proxy | 任务失败 | 按需 |
| file_transfer | 双向 | 传输文件 | 按需 |
| chunk_received | 双向 | 收到分片 | 每个分片 |
| shutdown | Proxy → Node | 关闭节点 | 按需 |

### 14.4 时间格式说明

所有时间戳使用 ISO 8601 格式：

```
格式: YYYY-MM-DDTHH:MM:SSZ
示例: 2023-01-01T12:00:00Z
```

- YYYY: 四位年份
- MM: 两位月份（01-12）
- DD: 两位日期（01-31）
- HH: 两位小时（00-23）
- MM: 两位分钟（00-59）
- SS: 两位秒数（00-59）
- Z: UTC时区标识
